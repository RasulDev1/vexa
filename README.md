# VEXA MEN — магазин в Telegram

Мини-приложение магазина и сервер к нему. Сервер отдаёт приложение, хранит каталог и фото
и пускает в «Управление товарами» только тех, чей Telegram ID указан в настройках.

## Как сервер понимает, кто администратор

1. Telegram передаёт мини-приложению данные пользователя (`initData`), подписанные токеном вашего бота.
2. Приложение отправляет их серверу с каждым запросом.
3. Сервер проверяет подпись токеном бота, поэтому подставить чужой ID без токена нельзя.
4. Если ID есть в `ADMIN_IDS`, пользователь видит кнопку «Управление товарами»
   и может добавлять и удалять товары. Остальным сервер отвечает «Нет прав»,
   даже если они попробуют отправить запрос в обход кнопки.

## Запуск — одним двойным щелчком

**Windows:** дважды щёлкните `START.bat`.
**Mac:** правый клик по `start-mac.command` → «Открыть» (только в первый раз, дальше двойным щелчком).

Программа всё сделает сама:

1. Если на компьютере нет Node.js, скачает переносную версию в папку `runtime` (один раз).
2. Спросит токен бота. Его выдаёт [@BotFather](https://t.me/BotFather) после команды `/newbot`.
3. Попросит написать боту любое сообщение, сама его дождётся и сделает написавшего администратором.
   Бот ответит «Вы администратор магазина». Узнавать свой Telegram ID не нужно.
4. Скачает туннель cloudflared и получит бесплатный HTTPS-адрес. Если Cloudflare недоступен,
   попробует другие бесплатные туннели: localhost.run и Pinggy (через встроенный в Windows SSH).
5. Запустит сервер и сама привяжет магазин к кнопке «Магазин» в боте. В BotFather ничего настраивать не нужно.

Когда в окне появится «✔ Магазин работает!», откройте бота и нажмите «Магазин».
Покупателям бот на /start и любое сообщение отвечает приветствием с кнопкой «Открыть магазин».

Если окно «замерло» после клика мышью, нажмите Esc: так Windows ведёт себя при выделении текста.
Вставлять токен удобнее правым кликом мыши.
Пока окно открыто, магазин работает. Если связь с туннелем пропадёт, программа переподключится
и обновит кнопку в боте сама. Остановить — закрыть окно или нажать Ctrl+C.

Ответы сохраняются в файле `.env`, поэтому при следующих запусках вопросов не будет.

Если Windows покажет «Система Windows защитила ваш компьютер», нажмите «Подробнее» → «Выполнить в любом случае».
Если туннель не запускается, возможно, провайдер ограничивает доступ к Cloudflare:
попробуйте другой интернет (например, раздачу с телефона) или VPN.

Токен бота никому не показывайте и не выкладывайте в открытый доступ:
с ним можно подделать вход администратора.

### Бесплатно в GitHub Codespaces (для практики)

Codespaces — бесплатный облачный компьютер от GitHub (до 60 часов в месяц на бесплатном аккаунте).
Туннель и VPN не нужны: GitHub сам даёт HTTPS-адрес, а у сервера есть прямой доступ к Telegram.

1. Создайте на github.com **приватный** репозиторий и загрузите в него файлы из этой папки
   (кнопка «uploading an existing file»). Файл `.env` не загружайте: в нём токен бота.
2. На странице репозитория: **Code → Codespaces → Create codespace on main**.
3. Когда откроется редактор, в терминале внизу выполните `npm start` и ответьте на вопросы.
4. Программа сама сделает порт публичным и привяжет адрес к кнопке «Магазин» в боте.

Codespace засыпает без активности (по умолчанию через 30 минут, можно увеличить до 4 часов
в github.com/settings/codespaces → Default idle timeout). Чтобы снова запустить магазин,
откройте Codespace и выполните `npm start`. Адрес при этом не меняется.

### Прокси

Если провайдер ограничивает доступ к `api.telegram.org`, программа сама использует прокси из настроек системы:
Windows — «Параметры → Сеть и Интернет → Прокси-сервер» (их обычно выставляют VPN-клиенты: v2rayN, Hiddify, Clash и т. п.),
macOS — настройки сети, а также переменные HTTPS_PROXY / ALL_PROXY. Поддерживаются HTTP- и SOCKS5-прокси.
Если прокси подвёл, запрос повторяется напрямую.

Прокси можно указать и вручную в `.env`:

```
PROXY=socks5://127.0.0.1:1080
PROXY=socks5://логин:пароль@адрес:порт
PROXY=http://127.0.0.1:8080
```

Прокси из настроек Telegram подойдёт, только если это SOCKS5. MTProto-прокси работает лишь внутри приложения Telegram.

### Запуск вручную (для разработчиков)

`npm start` делает то же, что `START.bat`. Только сервер, без туннеля: `npm run server`.

## Постоянная работа на своём сервере (VPS)

Подойдёт любой VPS с Ubuntu или Debian. Лучше за границей: у него будет прямой доступ к Telegram.

1. Скопируйте папку магазина на сервер. В PowerShell на Windows:
   `scp -r "C:\путь\к\temp-shop" root@IP_СЕРВЕРА:/root/`
2. Подключитесь к серверу: `ssh root@IP_СЕРВЕРА`
3. Выполните: `cd /root/temp-shop && sudo bash install.sh`

Скрипт сам установит Node.js и Caddy, спросит токен бота (если его ещё нет в `.env`),
попросит написать боту, получит бесплатный HTTPS-адрес вида `https://1-2-3-4.sslip.io`,
включит автозапуск и привяжет кнопку «Магазин» в боте. Свой домен: `DOMAIN=shop.ru sudo -E bash install.sh`
(сначала направьте домен на IP сервера).

Обновить код: скопируйте новые файлы в `/root/temp-shop` и снова выполните `sudo bash install.sh` —
товары, заказы и настройки сохранятся. Перезапуск: `sudo systemctl restart temp-shop`,
журнал: `sudo journalctl -u temp-shop -f`.

Бот может работать только в одном месте: после переезда на сервер не запускайте его в START.bat или Codespaces.

## GitHub Pages (бесплатно, без сервера)

На GitHub Pages магазин работает круглосуточно и бесплатно, без VPS и Codespaces:
- витрина, корзина, оформление заказа — заказ уходит менеджеру сообщением в Telegram с готовым текстом;
- **директор и менеджеры** добавляют и удаляют товары, фото, убирают цвета и размеры, ведут остатки.
  Изменения сохраняются прямо в репозиторий (`catalog/catalog.json` и `catalog/photos/`),
  покупатели видят их через 1–2 минуты.

Чего нет без сервера: заказов в приложении, реквизитов от бота и автоматического списания остатков.

**Публикация**

1. Создайте на GitHub **публичный** репозиторий (бесплатный Pages работает только с публичными).
2. Загрузите в него всё из этой папки, чтобы `index.html` лежал в корне. Файл `.env` и папки `data`, `runtime` не загружайте.
3. Откройте `js/config.js` (значок карандаша), впишите имя менеджера без @:
   `export const MANAGER_USERNAME = "ваш_логин";` → Commit changes.
4. **Settings → Pages**: Source — **Deploy from a branch**, Branch — **main**, папка — **/ (root)** → Save.
   Через 1–2 минуты сайт появится по адресу `https://ваш-логин.github.io/название-репозитория/`.
5. В @BotFather: `/mybots` → бот → **Bot Settings → Menu Button** → вставьте этот адрес.

**Роли: директор, менеджер, покупатель**

- **Директор** задаётся один раз в `js/config.js`: его Telegram ID (число от бота @userinfobot) и ФИО:
  `export const DIRECTOR = { telegramId: 123456789, name: "Иванов Иван Иванович" };`
  Директор управляет товарами, складом и назначает менеджеров («Сотрудники»).
- **Менеджеров** назначает директор в приложении: Telegram ID, ФИО и должность.
  Менеджер управляет товарами и складом, но не сотрудниками.
- **Покупатели** — все остальные.

У директора и менеджера справа сверху видны должность и ФИО. Роль определяется по Telegram ID того,
кто открыл магазин. Свой ID сотрудник видит внизу страницы: «Для сотрудников».

**Ключ доступа.** Чтобы изменения сохранялись в репозиторий, на устройстве сотрудника один раз вводится ключ
(«Для сотрудников» → «Сохранить ключ»). Ключи создаёт директор на GitHub — себе и отдельный каждому менеджеру:
github.com/settings/personal-access-tokens/new → Repository access — **Only select repositories** → ваш репозиторий →
Permissions → Repository permissions → **Contents: Read and write** → **Generate token**.
Сняв менеджера, удалите и его ключ на той же странице. Без ключа посторонний ничего не изменит,
даже если подделает роль.

**Pages вместе с сервером.** Если сервер магазина работает на постоянном адресе (VPS), впишите его в `js/config.js`:
`export const API_URL = "https://1-2-3-4.sslip.io";` — тогда на Pages заработает всё: склад, заказы, управление.
В `.env` на сервере укажите `PUBLIC_URL` = адрес на GitHub Pages, чтобы кнопки бота вели на сайт.

## Учёт товара и заказы

В «Управлении товарами» → «Изменить» включите «Вести учёт количества» и впишите остатки
для каждого сочетания цвета и размера. При каждом заказе сервер проверяет остатки и списывает их.
Если двое покупателей одновременно берут последнюю вещь, заказ получит только первый,
второму приложение сообщит, что товар закончился.

О каждом заказе сервер пишет администраторам в Telegram. Чтобы сообщения приходили,
каждый администратор должен один раз открыть чат с ботом и нажать «Старт».
Если указать `PUBLIC_URL` (адрес магазина), в сообщении будет кнопка «Открыть заказ».

## Обработка заказа

В приложении у администратора есть кнопка «Заказы». У нового заказа два действия:

- **Принять** — впишите реквизиты для оплаты: номер карты, банк и получателя или ссылку на оплату,
  и, если нужно, комментарий. Покупатель получит от бота сообщение с суммой и реквизитами
  (если реквизиты — это одна ссылка, ещё и кнопку «Оплатить»). Реквизиты также видны
  в «Моих заказах» с кнопкой «Скопировать». Приложение запоминает последние реквизиты и подставляет их.
- **Нет в наличии** — поправьте текст сообщения и отправьте. Покупатель получит его от бота,
  а товар из заказа вернётся на склад.

После решения у заказа появляется ссылка на покупателя в Telegram, чтобы написать ему напрямую.
Покупатель видит статус и реквизиты для оплаты во вкладке «Мои заказы».
Перед оформлением заказа приложение просит покупателя разрешить боту писать ему.
Если он отказался, приложение покажет, что сообщение не доставлено: напишите покупателю по ссылке.

## Онлайн-оплата картой (Stripe)

Только для GitHub Pages с Supabase. Когда менеджер принял заказ, у покупателя в «Моих заказах»
появляется кнопка «Оплатить картой онлайн». Сумма берётся из базы, после оплаты заказ сам становится
«Оплачен» (в аналитике — как оплата картой), а бот пишет покупателю «Оплата получена».
Реквизиты и кнопка «Оплатить» у менеджера работают как раньше.

Сначала подключаются **тестовые ключи** Stripe: деньги не списываются. Для них нужна только почта,
ИП и самозанятость не нужны.

1. Зарегистрируйтесь на [dashboard.stripe.com/register](https://dashboard.stripe.com/register) (страну можно выбрать любую).
   Вы сразу в тестовом режиме (Sandbox): в Developers → API keys скопируйте **Secret key** (`sk_test_…`).
2. Supabase → SQL Editor: запустите `supabase-online-pay.sql` (после `supabase-payments.sql`).
3. Supabase → Edge Functions: создайте функцию `online-pay` с кодом из `supabase/functions/online-pay/index.ts`
   и **выключите Verify JWT** (или `supabase functions deploy online-pay --no-verify-jwt`).
4. Edge Functions → Secrets: `STRIPE_SECRET_KEY` и `PAY_TESTERS` — свой Telegram ID
   (через запятую, если проверяющих несколько). С тестовым ключом платить могут только они.
   Необязательно: `PAY_RETURN_URL` — куда вернуть после оплаты, например `https://t.me/имя_бота`.
5. Stripe → Developers → Webhooks → Add destination: адрес `https://<проект>.supabase.co/functions/v1/online-pay`,
   событие `checkout.session.completed`. Без него оплата тоже отметится — когда покупатель вернётся в магазин.
6. `js/config.js`: впишите свой Telegram ID в `ONLINE_PAY_TESTERS` — кнопку увидите только вы.
   Тестовая карта: `4242 4242 4242 4242`, срок — любой в будущем, CVC — любые 3 цифры.

Принимать настоящие деньги Stripe будет только после проверки компании, и с российскими картами он не работает.
Для боевой оплаты в России понадобится ЮKassa, CloudPayments или эквайринг банка (нужны ИП или самозанятость):
поменяется только функция `online-pay`, кнопка и база останутся.

## Как добавить или убрать администратора

Измените `ADMIN_IDS` в `.env` (ID через запятую) и перезапустите магазин.

## Где хранятся данные

- `data/catalog.json` — добавленные товары, скрытые встроенные товары и убранные цвета и размеры;
- `data/orders.json` — все оформленные заказы;
- `data/images/` — фото товаров.

Делайте резервную копию папки `data`. Если хостинг стирает диск при перезапуске,
подключите постоянное хранилище, иначе добавленные товары пропадут.

## Адреса сервера

| Адрес | Кто может | Что делает |
|---|---|---|
| `GET /` | все | приложение |
| `GET /api/catalog` | все | каталог |
| `GET /api/me` | все | проверка, администратор ли пользователь |
| `POST /api/products` | админ | добавить товар с фото |
| `DELETE /api/products/:id` | админ | удалить товар и его фото |
| `PUT /api/hidden` | админ | скрыть или вернуть встроенные товары |
| `PUT /api/variants/:id` | админ | убрать отдельные цвета, размеры или сочетания у товара |
| `PUT /api/stock/:id` | админ | задать остатки на складе по цветам и размерам |
| `POST /api/orders` | пользователь Telegram | оформить заказ: проверка и списание остатков, уведомление админам |
| `GET /api/my-orders` | пользователь Telegram | свои заказы со статусом и реквизитами для оплаты |
| `GET /api/orders` | админ | список заказов |
| `POST /api/orders/:num/accept` | админ | принять заказ и отправить покупателю реквизиты для оплаты |
| `POST /api/orders/:num/reject` | админ | отказать, вернуть товар на склад и написать покупателю |
